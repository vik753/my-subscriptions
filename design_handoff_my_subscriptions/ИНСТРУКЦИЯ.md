# Пошаговая инструкция: как собрать PWA в Claude Code

Этот файл для вас. Технические детали для Claude Code лежат в `README.md`.

## 0. Подготовка (один раз)
1. Установите **Node.js LTS** (nodejs.org) и **Git**.
2. Установите Claude Code: `npm install -g @anthropic-ai/claude-code`, запустите `claude` и войдите в аккаунт.
3. **Google Cloud Console** (console.cloud.google.com):
   - создайте проект;
   - включите **Google Calendar API** и **Google Drive API**;
   - настройте «OAuth consent screen» (External), добавьте себя в тестовые пользователи;
   - создайте «OAuth client ID» типа **Web application» и добавьте в Authorized JavaScript origins `http://localhost:5173` (позже — адрес вашего сайта);
   - сохраните **Client ID**, его попросит Claude Code.
4. Распакуйте архив в пустую папку, откройте в ней терминал и запустите `claude`.

## 1. Каркас PWA
> Прочитай `design_handoff_my_subscriptions/README.md`, посмотри `screenshots/` и `tokens/`. Создай в корне проект Vite + React + TypeScript с vite-plugin-pwa. Подключи шрифт Inter и Phosphor Icons. Перенеси темы из `tokens/theme-tokens.json` (4 схемы × светлая/тёмная) и строки из объекта `L` в `design/Абонементы.dc.html` в i18n (uk/en/ru). Пока без экранов.

Проверка: `npm run dev` → откройте http://localhost:5173.

## 2. Логика занятий и оплат
> Реализуй модель данных и правила из «Data model» и «Core rules» README, включая правило «ждёт ответа». Храни данные в IndexedDB. Напиши тесты Vitest на все правила.

Проверка: `npm test`, все тесты проходят.

## 3. Вход через Google
> Сделай экран входа (скриншоты 15) через Google Identity Services с доступами calendar.app.created и drive.appdata. Client ID: <вставьте свой>. Состояния: загрузка, ошибка, отказ в доступе.

## 4. Основные экраны
> Сделай Home (две вкладки: «Абонементы» и «Общий календарь»), Hobby detail, Create/Edit (длительность: ввод или варианты 30/45/60/90/120), Add payment и Session sheet по README и скриншотам 01–08, 12, 13, 18, 22.

## 5. Проверка при открытии
> Реализуй раздел «App open check»: вопрос по одному занятию (11), список прошедших занятий (17), напоминание о продлении с откладыванием на день, теги «Не отмечено» и стиль клетки «без отметки».

## 6. Google Calendar
> Реализуй раздел «Google Calendar» README: отдельный календарь «My Subscriptions», события с названием, цветом и описанием, напоминание из настроек, обновление только изменившихся событий.

Проверка: создайте хобби и откройте Google Calendar в браузере.

## 7. Синхронизация и офлайн
> Реализуй раздел «Storage & sync»: резервная копия в Google Drive appDataFolder, очередь изменений без сети, компонент статуса (скриншот 19).

Проверка: в DevTools включите Offline, внесите изменения, выключите Offline.

## 8. Настройки, установка, компьютер
> Сделай Settings (09, 14, 20), About (10), подсказку установки (16) и раскладку для компьютера (21) по README.

## 8.1. Анимации
> Добавь анимации из раздела «Motion» README: появление экранов, выезд нижних панелей снизу и плавное закрытие, появление и исчезновение тостов, раскрытие строк дней и вариантов длительности. Учти prefers-reduced-motion.

## 9. Иконки и публикация
> Сделай из `icons/app-icon-nocturne-dark.png` векторную иконку, выгрузи 192, 512, maskable 512 и apple-touch-icon 180, подключи в manifest. Подготовь деплой на Vercel.

Дальше:
- выполните `npx vercel` и добавьте полученный адрес в Authorized JavaScript origins в Google Cloud;
- для публичного доступа отправьте OAuth consent screen на проверку Google, потому что используются доступы к Calendar и Drive.

## Советы
- Давайте Claude Code по одному шагу и проверяйте результат перед следующим.
- Проверяйте на iPhone в Safari (Поделиться → На экран «Домой») и на Android в Chrome.
- Если что-то не так, пришлите скриншот и номер экрана из `screenshots/`.
- Прототип можно открыть так: `npx serve design_handoff_my_subscriptions/design`, затем `Абонементы.dc.html`.
